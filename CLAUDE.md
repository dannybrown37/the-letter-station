# The Letter Station

Learning game for the user's son (autistic). Special interests: letters, The Learning Station, Blippi, Little Baby Bum, Sing movies, US states, stores, restaurants, snacks. He loves asking "what states have a Publix?" Content should feed those interests.

## Hard constraints

- **Mobile first, phone only.** Portrait, ~390px wide. Exception: Key Shop may turn (`canTurn()` in app.js); its studio goes side by side in landscape (`.bench.studio`). No desktop app planned. Big tap targets (≥48px), no hover-only UI, `font-size: 16px` on inputs (stops iOS zoom).
- **No build step, no dependencies.** Plain HTML/CSS/ES modules. Installable PWA (`manifest.webmanifest`). Must work when hosted as static files.
- **Kind feedback.** Wrong answers never end a round — he keeps tapping until he finds it (`choiceButtons` in `js/app.js`). No timers, no losing, no harsh sounds (sine/triangle only). Wrong taps look dimmed + dashed, never red.
  - Approved exception (user asked, Nov 2026): Bike Ride is endless and a run ends after 3 missed target letters (`HEARTS` helmets). Everything else stays kind: lost helmets go dim + dashed, soft sine/triangle sounds, a hint every miss, and the end card celebrates the score ("What a ride! 23 letters!"). Don't spread this to other games without asking.
- **Rewards.** A right answer calls `celebrate(extra, fromEl, scored())`: ding, 20ms `navigator.vibrate` tick, confetti, a ⭐ that flies from `fromEl` to the top-bar count, one spoken line from `rewardLine()` (never two `say()`s in a row: the second cancels the first). Quiz cards show `streakLine()`: the 5-star trail (`starTrail`, session count, never drops on a wrong tap; full = party) plus the 🔥 streak text. Exception: run-based canvas games (pancake, bike) call `celebrate` once per finished run, not per hop/flag (user asked for one celebrate at the finish); per-step hits get a local ding + sparkle.
- Each game's top bar and `theme-color` use its GAMES color, darkened with `shade()` (`tint()` in `route()`); new games get this for free.
- Tab rows never wrap; rows with 4+ tabs shrink their font (`.tabs:has(> :nth-child(4))`). Keep labels short.
- **Read aloud, with a top-bar toggle (🔊/🔇, localStorage `narration`).** `say()` = automatic narration, obeys the toggle. `speak()` = something he tapped to hear (🔊 Hear it, word chips, kind badge); always talks. Use the right one.
- **Dark theme only** (user asked: the light theme was too bright). Use the `--bg/--card/--panel/--ink/--muted/--line` vars, never `#fff` backgrounds. Brand-colored text goes through `brandText()` so dark brand colors stay readable.
- Respect `prefers-reduced-motion` (already handled in CSS).
- User-entered text (video titles/questions) goes in via `textContent` only — the `h()` helper never uses innerHTML. Keep it that way.
- Don't hardcode YouTube video IDs or image URLs from memory; they rot or are wrong. Parent pastes videos; store images come from Wikipedia at runtime.
- Exception: video packs (`SING_VIDEOS` in data.js) are OK if each ID was found by search and checked with YouTube oEmbed (`https://www.youtube.com/oembed?format=json&url=...` → 200). Rows whose thumbnail is YouTube's 120x90 placeholder are hidden at runtime (`isDeadThumb`). Same rule for `LBB_CHARACTERS[].video`: the character picture is that official LBB video's thumbnail (`x` = crop focus %); falls back to the emoji.

## Layout

```
index.html            shell: topbar (home btn, title, narration toggle, star count) + <main id=app>
style.css             all styles; CSS vars in :root
manifest.webmanifest  PWA
icon.svg
sw.js                 service worker: offline. Own files network-first (deploys show up at once), Wikipedia images cache-first. Add new app files to SHELL_FILES.
js/data.js            STATES, KINDS, STORES, WORDS, CATEGORY_INFO, VIDEO_QUESTIONS, VIDEO_CHANNELS
js/logic.js           pure, testable: question generators, letter helpers, parseYouTubeId
js/keyshop.js         Key Shop game (canvas painting, synthesized sounds, animations); gets h/screen/say/... from app.js
js/<game>.js          newer games (spotter, lineup, shopping): UI module, gets kit() from app.js; pure rules in js/<game>-logic.js
js/usmap.js           US_VIEWBOX, US_PATHS (SVG path per state), US_LABELS (label point per state). Generated once from Wikimedia "Blank US Map (states only).svg" (CC0); AK/HI are insets. Don't hand-edit the paths
js/app.js             DOM: h() + svg() helpers, speech/sounds/confetti, stars, screens, hash router
test/*.test.js        node:test, table-driven, seeded RNG
```

Flow: `location.hash` → `route()` → `GAMES[i].run()` → `screen(title, ...nodes)` replaces `<main>`.

To add a game: write a `run` function using `screen()`, add an entry to `GAMES`. Games in their own module get shared helpers from `kit()` in app.js and inject their own `<style>` (keeps style.css for shared pieces). Home shows 3 tiles per row and fits one phone screen without scrolling (user asked: less scrolling); the grid is 6 columns and each tile spans 2, so leftover tiles stretch: one over a multiple of 3 becomes a full-width banner, two over share the last row half-and-half (CSS in `.tile:last-child:nth-child(3n + …)`). Any tile count works; no row ends with a gap. Long pick-lists go in a sideways `strip()`, not a wall of chips. `h()` style supports `--custom` props.

Jacus, Pig and Daisy the cow were added Oct 2026 at the son's request (confirmed by official video titles). William the chicken's name comes from the son; no official source found. ## Data rules

- `STORES` mixes regional and national chains (user asked for Walmart, Target, etc.). Each store has `name, wiki?, emoji, color, kind, states[]`. Use `ALL` / `allExcept(...)` in data.js for near-national chains. `HUNTABLE_STORES` (logic.js) leaves out stores in all 50 states.
- `kind` must be a key of `KINDS` (grocery, gas, restaurant, superstore, home, craft, furniture, warehouse). Tests enforce this, and that every state code is real.
- Footprints are approximate. The original 22 came from memory; the Oct 2026 additions were web-researched (store locators, Wikipedia, ScrapeHero). Look up new stores the same way, don't guess. If the user corrects one, just update it.
- The user's family likes FL chains (Busy Bee, Vale, 4 Rivers) and Utah/West chains (Zupa's, R&R, Stater Bros). Vale = Vale Food Co, labeled just "Vale".
- `wiki` is optional = English Wikipedia page title; `storeImageUrl()` fetches `/api/rest_v1/page/summary/{wiki}` thumbnail, caches in localStorage `storeImages`, falls back to emoji. Verify titles before adding (disambiguation pages have no image, e.g. Bojangles → `Bojangles_(restaurant)`). No page: Busy Bee, Zupa's, Vale, 4 Rivers, R&R. No image: Fred Meyer, Stater Bros, Cafe Rio. Wikipedia rate-limits bursts from curl, so add a User-Agent and sleep ~4s between titles.
- `WORDS` entries must start with a letter (firstLetter skips digits, so "4 Rivers" would land under R).
- `WORDS` (stores/restaurants/snacks/states) feeds the letter games; anything goes here, national chains included.

## localStorage keys

`stars` (number), `narration` (bool), `videos` ([{id,title,questions[]}]), `storeImages` ({wiki: url|""}), `keyboard` ({keyId: {c: "#hex", f: finishId, img?: "data:image/jpeg;base64,..."}}; old bare "#hex" saves migrate in `loadKeyboard`), `keyGallery` ([board], complete boards only), `passport` ({stamps: [code], at: code|null, trips: n}, cleaned by `loadPassport`), `pancakeBest` (number), `bikeBest` ({letter: n, switch: n}; old bare numbers are ignored). Snapshots are small JPEGs (~1-2KB/key); if localStorage is full, hanging fails with a "gallery is full" message.
